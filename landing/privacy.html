Privacy Policy

Your browser data stays
on your machine.

TurboWeb MCP is a browser extension plus a local daemon. The extension has exactly one place to send anything: a server process running on 127.0.0.1 on your own computer. There is no TurboWeb MCP cloud, no account, and no server of ours anywhere in the picture.

Last updated: 13 November 2026

The short version

  • No analytics, no telemetry, no crash reporting. Nothing is measured, and nothing is sent anywhere for us to read.
  • No accounts, no sign-in, no identifiers that follow you. The extension generates two random UUIDs that never leave your browser.
  • No cloud. The extension speaks only to 127.0.0.1 — the daemon you installed.
  • No selling, sharing, or transferring of data to third parties. There is nothing to sell; we never hold your data to begin with.
  • Two optional exceptions, both yours to configure: if you set an AI provider API key, the daemon may send page content to that provider; and the daemon checks GitHub for new releases.

01Who this policy covers

This policy covers two pieces of software that work together:

  • The browser extension — what you install from the Chrome Web Store (or Firefox Add-ons, or load unpacked from a release zip). This is the part the store's data-disclosure form describes.
  • The daemon — the turboweb-mcp-by-ikari binary you run separately. It is open source, distributed from GitHub Releases, and not distributed by any browser store.

It is published by Cezar "ikari" Pokorski, an individual developer. Contact: privacy@ikari.software.

02What the extension can see, and where it goes

The extension is a bridge. An AI agent asks the daemon to do something — click an element, read the page, take a screenshot — and the daemon relays that request to the extension, which performs it in your browser and sends the result back.

That means the extension can read the contents of the tabs you point it at: page text, the DOM, form field values, screenshots, and the list of your open tabs. It needs those capabilities to function at all. What matters for privacy is where they go: back down the loopback connection to the daemon on the same machine, and nowhere else.

The extension makes network requests to exactly three addresses, all loopback:

EndpointPurpose
ws://127.0.0.1:18321The daemon. Carries every command and its result. Loopback-only, no TLS, never exposed off-host.
http://127.0.0.1:18322Optional native image resizer for screenshots. If absent, the extension resizes in-browser instead. No data leaves the machine either way.
http://127.0.0.1:18323Loopback file host used only by the drag-and-drop tool. A single-use, 32-byte, ~30-second token gates each fetch; the request carries no filesystem path.

There are no other outbound requests. No analytics SDK, no crash reporter, no ad network, no remote config, no font or script CDN. The extension ships every asset it uses. You can verify this: the source is in extension/ in the public repo, and the built zip contains only those files.

03What the extension stores

The extension keeps a handful of small values in the browser's local extension storage. It uses storage.local and storage.session — never storage.sync, so none of it is uploaded to your Google or Mozilla account.

ValueWhere and why
instanceIdstorage.local. A random UUID generated on first run, used to tell one browser profile from another when several are connected. Not derived from hardware, network, or account.
askBeforeConnectstorage.local. Your toggle for whether an agent must ask permission before taking control. Defaults to on.
sessionIdstorage.session. A random UUID regenerated each browser session. Cleared when you close the browser.
approvedAgentsstorage.session. Which agents you said yes to this session. Cleared when you close the browser.
deniedAgentsstorage.session. Which agents you said no to this session. Cleared when you close the browser.

Nothing else is persisted. This is not a user profile and it is not shared with anyone: it exists so the extension knows which local process is which and does not re-prompt you every 25 seconds.

How to delete it

Removing the extension from chrome://extensions deletes its storage along with it. The storage.session values disappear on their own every time you close the browser — approvals are per-session by design, so you are not permanently trusting an agent you said yes to once.

04What the daemon does differently

The daemon is a separate program on the same machine, and it has three optional interactions with the internet. The extension is not involved in any of them, and none of them happen unless you set them up.

AI post-processing — off unless you supply a key

Four tools accept a question argument and pipe page data through a model when you use it: extract_text, find_text, and inspect go through the cascade below; describe always uses Anthropic (it sends a screenshot too) and returns raw data if no key is present. Which model answers is decided by TURBOWEB_AI_BACKEND, whose default only reaches for a cloud provider if you have given it a key:

  • ANTHROPIC_API_KEY (or CLAUDE_API_KEY) — page content, screenshot, and question are sent to api.anthropic.com, under Anthropic's terms and privacy policy.
  • GEMINI_API_KEY — the same, to generativelanguage.googleapis.com, under Google's terms.
  • TURBOWEB_AI_BACKEND=local — Chrome's built-in Gemini Nano, which runs on your device. Nothing leaves the machine.
  • TURBOWEB_AI_BACKEND=none — never post-process; always return raw data. This is the hard guarantee: with none, no page data can reach a model regardless of what keys are set.

With no key set and no local backend available, the default cascade quietly falls through to raw data — nothing is transmitted. The tools still work; they just return JSON instead of prose. This is the one place where page data can go to a third party, and it is you who enables it — with your own key, on your own account, for a page you chose to ask about.

Update check — to GitHub only

The daemon asks api.github.com whether a newer release exists, so connection_status can tell you. This request carries a User-Agent of turboweb-mcp/<version> and an API version header — no identifiers, no page data, no telemetry payload, no machine name. GitHub sees a request from your IP, as it does for any web page you load. Downloads from Releases go to the same place.

Files on your disk

Local state, not transmitted anywhere:

  • ~/.config/turboweb-mcp-by-ikari/ (or the XDG / %APPDATA% equivalent) holding browser.json for launch preferences, turboweb.db (SQLite) for any custom tools you define, and optionally a dedicated Chrome profile directory.
  • capture_page saves a full-page HTML snapshot to capture-*.html in a 0700 temp directory — because the point of that tool is to hand you a file. It is written with 0600 permissions and stays on your disk.

05Chrome Web Store Limited Use compliance

The Chrome Web Store's User Data Policy requires a clear statement about how extension data is handled. TurboWeb MCP's extension:

  • Handles browser data (page content, tab list, screenshots) only to perform the user's own request — the feature the user asked the agent to carry out.
  • Does not transfer browser data to any third party, except where that is the user-initiated feature itself (an agent driving the browser). No advertising, no analytics, no data brokers.
  • Does not use or transfer browser data to determine creditworthiness or for lending purposes.
  • Does not sell browser data.
  • Serves a single, clearly disclosed purpose: connecting the user's browser to a local AI-agent daemon.

06Security, and the honest limits

Loopback-only is the entire authentication boundary. Any local process that can reach port 18321 can attempt to talk to the daemon — that is why the extension prompts you before an agent takes control, and why you should not run untrusted local code under the same user account while turboweb is running. The README's security notes and SECURITY.md go into this in more detail.

Release binaries are notarized on macOS and published with SHA256 checksums signed by keyless cosign against the release workflow's identity, so you can verify that what you downloaded is what CI built.

07Changes to this policy

If the data handling changes — a new outbound endpoint, a new stored value — this page changes with it, in the same commit as the code, and the date at the top moves. The page's full revision history is public in the repository.
